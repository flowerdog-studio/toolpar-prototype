# Toolpar — дизайн-система, прототип и перенос в прод

Отвечай на русском. Работай как старший продуктовый дизайнер и фронтенд-разработчик одновременно: решения опирай на современные паттерны (Baymard, Apple HIG, Material) и на правила этой системы. Чистоту системы держи сам, не дожидаясь просьбы.

## Источники (в порядке приоритета)

1. **Прототип** — репозиторий `toolpar-prototype`, папка `dev-dfc314/` (`index.html`, `content.json`, `help.json`, `img/`). Эталон поведения и мобильной вёрстки.
2. **Figma «Toolpar DS»** — токены, текстовые стили, компоненты, макеты веба. Страницы: Getting started, Foundations, Components / *, Layouts / Desktop и Mobile, Changelog.
3. **`dev-dfc314/docs/`** — спецификация для разработки: `README.md`, `design-system.md`, `components.md`, `pages.md`, `production.md`, `tokens.css`, `tokens.json`, `screens/`.

Перед любой работой прочитай `docs/README.md` и раздел `docs/`, относящийся к задаче. В Figma читай страницы и компоненты по именам (ID могут меняться) и все аннотации.

## Незыблемые правила

- Без скруглений. Шрифт Inter. Иерархия — размером и весом, цвет — только для действий и статусов.
- Жёлтый `#FFFC39` (`--action-primary-default`) — только главное действие; hover и pressed — `#FFFD7E`. Рассрочка — красный с иконкой банка. Чёрная кнопка (Button Type=Dark) — только на жёлтых баннерах.
- Старая цена всегда зачёркнута. Название в карточке товара — ровно 3 строки, бренд жирнее.
- Сетка 1440: поля 60, 5 колонок по 240, гаттер 30, полуколонки 105 (типовые ширины 240/375/510/645/780/915/1320). Мобилка 375: поля 16, гаттер 12, 2 карточки. Переключение вёрстки ≤ 767 px.
- Отступы только по шкале 2/4/8/12/16/20/24/32/40/48/60. Хедер → контент 40, заголовок секции → контент 32, между секциями 96–120.
- Только токены и стили: цвета — `var(--…)` / переменные Color, тексты — классы `.t-*` / текстовые стили. Новый цвет, кегль или компонент — только после проверки, что такого нет; если почти такой есть — правь базовый, а не создавай дубль.
- Неразрывный пробел после коротких слов (1–2 буквы, «для, без, при, под, над, про, из-за, что, как, или»).
- Заголовки короткие и человечные, без пафоса.

## Работа в Figma

- Страницы собирай только из инстансов компонентов и токенов, на реальном контенте.
- После правок: удалить неиспользуемое (getInstancesAsync = 0), дубли стилей, служебные слои; проверить скриншотом; записать изменения в Changelog.
- Ловушки API: `resize()` фиксирует размер — потом верни hug; клонированный вариант теряет `componentPropertyReferences` — перепривяжи; картинки загружай через upload_assets с nodeIds; sticky и видео-заливки — ручные шаги дизайнера.

## Работа с прототипом

- Один файл `index.html`: CSS (токены → компоненты → `.m` мобильная версия), веб-рендер (`render()`, `go(view)`), мобильный (`mRender()`, функции `M*`), корзина/ЛК и новые страницы в третьем `<script>` (экспорт в `window`).
- Проверка: локальный сервер и скриншоты Playwright на 1440 и 375, ошибки консоли = 0.

## Перенос в продакшн

Следуй `docs/production.md`: прототип — эталон, не код для прода. Брать как есть: `tokens.css`, значения CSS, тексты, изображения (с готовыми кропами), геометрию карты, логику интерфейса. Переписать: роутинг (реальные URL, SSR), состояние (store + API), адаптив одной разметкой, заглушки-тосты → настоящие сценарии, SEO (убрать noindex), доступность, производительность. Приёмка — сравнение со `screens/` и состояниями из Figma.

## Открытые вопросы (не решать самостоятельно)

Значения уровней «Резидент» и «Партнёр» и ответы FAQ «Системы привилегий»; планшетная вёрстка 768–1279; контраст серого текста `#939393`; страницы, которых нет в прототипе (см. `production.md`). Если задача их касается — спроси заказчика или предложи вариант явно как допущение.
