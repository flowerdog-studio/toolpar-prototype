# Перенос в продакшн

## Порядок работ

1. **Фундамент.** Подключить `tokens.css` (или `tokens.json` в Tailwind / Style Dictionary), шрифт Inter (кириллица + латиница, 400/500/600/700/800, `font-display: swap`), иконки из Figma *Foundations* или объекта `ICONS` прототипа.
2. **Базовые компоненты** по `components.md`: Button, IconButton, Link, SearchField, Checkbox, Stepper, Badge, Price, Tab, SectionHeader, FaqItem. Проверить все состояния (hover, pressed, disabled, focus) по Figma.
3. **Каркас:** UtilityNav, ShoppingNav (sticky), CatalogMenu, Footer. Мобильные M/Header и M/TabBar.
4. **Коммерция:** ProductCard (все состояния), категория с фильтрами, товар, корзина и оформление, «Спасибо», заказ в ЛК.
5. **Контентные страницы:** Покупателям (хаб и статьи), Акции, Бренды, О компании, Система привилегий.
6. **Мобильная версия** — каждая страница сразу в двух вёрстках; приёмка по `screens/mobile-*.jpg`.
7. **SEO, доступность, производительность, аналитика** — по чек-листам ниже.

## Что брать из прототипа как есть

- **Токены и значения CSS:** цвета, кегли, отступы, размеры, переходы. Все цвета прототипа уже заменены на `var(--…)`. Исключение — служебные цвета-заглушки под фото и видео (`#1b1b1b`, `#3a3a3a`, `#6b6b6b`), их можно оставить.
- **Тексты:**
  - раздел «Покупателям» — `help.json`;
  - «О компании» — константы `AB_*`;
  - «Система привилегий» — `LP_*`;
  - баннеры и акции — `HERO`, `PROMO`.
- **Геометрия карты** «О компании» (`AB_MAP` — контуры, `AB_CITIES` — координаты городов) и расчёт масштаба в `AboutPage()`.
- **Изображения** из `img/`. Это уже нужные кропы: веб, `@2x` и мобильные (`-m`, `@3x`). Подробности — в разделе «Изображения».
- **Логика интерфейса:**
  - автопрокрутка баннера (6 с, пауза в скрытой вкладке);
  - карусели (стрелки неактивны на краях, свайп и перетаскивание);
  - листание фото в карточке по зонам при наведении;
  - группировка корзины по отправлениям;
  - поиск по статьям с подсветкой;
  - оглавление статьи с подсветкой текущего раздела;
  - аккордеоны.

## Что переписать

| В прототипе | В продакшне |
|---|---|
| `go(view)` и один URL | Настоящие маршруты с SSR. Например: `/`, `/catalog/<slug>`, `/product/<slug>`, `/cart`, `/checkout`, `/order/success`, `/account/orders/<id>`, `/help`, `/help/<article>`, `/promos`, `/promos/<slug>`, `/brands`, `/brands/<slug>`, `/about`, `/loyalty`. |
| Состояние `S` в памяти | Store (Pinia / Vuex) и API. Корзина хранится на сервере или в localStorage. |
| `content.json`, `img/c/*.json` — демо-данные с tssp.kz | API каталога: категории, товары, фильтры, остатки, доставка. |
| Две вёрстки, переключаемые JS по ширине ≤ 767 px | Одна разметка, адаптив через CSS `@media (max-width: 767px)`. Разные компоненты — только там, где мобильный UX другой: шторки фильтров, липкая покупка, нижняя панель, каталог списком. |
| Заглушки-тосты «в следующей версии» | Настоящие сценарии: регистрация и вход, «Заказать звонок», «Стать клиентом», «Стать участником», страницы акции и бренда, карта пунктов выдачи, редактирование получателя и адреса, отмена заказа, список заказов. |
| `typo()` на клиенте | Неразрывные пробелы при рендере на сервере или в CMS (правило — в `design-system.md`). |
| Видео рилсов из `media/` | Хостинг видео или CDN, постеры, `preload="none"`. |

## Адаптивность

- Нарисованы и проверены две ширины: **1440** (веб) и **375** (мобилка). Вёрстка переключается на 767 / 768 px.
- Шире 1440 контент остаётся 1320 по центру, растут поля. Шапка «О компании» тянется на всю ширину окна.
- **Планшеты (768–1279)** отдельно не рисовались. Рекомендация:
  - веб-вёрстка с полями 32;
  - сетки карточек 3 в ряд;
  - сайдбары сохранить от 1024, ниже — шторки как на мобилке.

  Согласовать с дизайнером до разработки.
- Учитывать safe area на iPhone (`env(safe-area-inset-*)` — в прототипе так сделаны хедер и нижняя панель).

## Изображения

- **Форматы:** AVIF или WebP с JPEG-запасным вариантом, `srcset` для 1x и 2x (мобилка 2x и 3x). Фиксированные пропорции (`aspect-ratio`), чтобы не было сдвигов вёрстки. Ниже первого экрана — `loading="lazy"`.
- **Фокус кадра:**
  - шапка «О компании» на вебе — `object-position: 60% 30%`;
  - на мобилке — отдельный кроп 4:5;
  - баннер «Системы привилегий» — картинка уже собрана под 1320 × 570, на мобилке своя.
- **Фото товаров** — на сером `--bg-tertiary`, `object-fit: contain`, квадрат.
- **Логотипы клиентов и брендов** — SVG или PNG с прозрачностью. Серый вид задаётся CSS-фильтром (`grayscale(1)`, `opacity .75`), отдельных серых файлов не нужно.
- **Новые картинки** для баннеров нужно готовить с тем же жёлтым `#FFFC39`, если баннер жёлтый, иначе будет виден шов.

## SEO

- Убрать `<meta name="robots" content="noindex">` из прототипа: в продакшн он попасть не должен.
- **Метаданные:** уникальные `title` и `description` на каждой странице, один `h1` на страницу (в макетах он всегда есть), Open Graph.
- **Микроразметка Schema.org:** `BreadcrumbList`, `Product` с `Offer` и `AggregateRating`, `Organization`, `FAQPage` на «Покупателям» и «Системе привилегий».
- **Чистые URL, sitemap, canonical** у фильтров категорий.

## Доступность

- **Видимый фокус** — `:focus-visible` с обводкой 2 px (есть в `tokens.css`).
- **Ссылки и кнопки:**
  - переходы — ссылки `<a>`, действия — `<button>` (в прототипе почти всё сделано кнопками);
  - карточки разделов и товаров — одна ссылка на всю карточку.
- **Карусели:** у стрелок `aria-label`, ленты прокручиваются с клавиатуры, автопрокрутка баннера останавливается при фокусе и наведении.
- **Аккордеоны** — `aria-expanded`, **шторки** — `role="dialog"`, ловушка фокуса, закрытие по Esc.
- **`alt`** у всех содержательных фото. У логотипов — название компании.
- **Контраст.** Серый `--text-secondary` `#939393` на белом даёт 3,07:1. Этого хватает для крупного текста и подписей от 18 px, но меньше AA (4,5:1) для мелкого. Это сознательное решение дизайна для второстепенных подписей. Если нужна строгая AA, можно затемнить токен до `#767676` — тогда поменяется везде одной строкой. Решение за заказчиком.
- **`prefers-reduced-motion`** отключает анимации (в прототипе уже есть).

## Производительность

- Критический CSS, шрифты с `preload` для 500 и 700.
- Первый слайд баннера и шапка — `fetchpriority="high"`, остальные слайды — lazy.
- Карусели — без тяжёлых библиотек: в прототипе хватает нативной прокрутки и `scroll-snap`.
- Ориентиры — Core Web Vitals: LCP < 2,5 с, CLS < 0,1, INP < 200 мс.

## Аналитика (предложение)

Минимальный набор событий:
- `view_item_list`, `view_item`, `add_to_cart`, `begin_checkout`, `purchase`;
- клик «В рассрочку», поиск, использование фильтров;
- открытие рилса, «Заказать звонок», «Стать участником».

## Приёмка

1. Каждую страницу сравнить со скриншотами `screens/` на 1440 и 375. Затем пройти сценарии в прототипе: наведения, раскрытия, карусели, шторки, корзина → «Спасибо».
2. Проверить по Figma состояния компонентов и токены (Dev Mode показывает CSS-имена переменных).
3. Проверить:
   - нет скруглений;
   - жёлтый только у главного действия;
   - старая цена зачёркнута;
   - предлоги не висят;
   - названия в карточках — ровно 3 строки.
4. Lighthouse: Performance, Accessibility, SEO — 90+ на главной, категории и товаре.

## Открытые вопросы к заказчику

- **«Система привилегий»:** значения уровней «Резидент» и «Партнёр» (оплата бонусами до 75% и до 100%, скидка на межгород 15% и 20%) и ответы в «Частых вопросах» — черновик, нужно подтвердить.
- **Планшетная вёрстка 768–1279** — см. раздел «Адаптивность».
- **Контраст серого текста** — см. раздел «Доступность».
- **Сценарии**, которые в прототипе заглушены тостами (список выше).
- **Страницы**, которых нет в прототипе: карточка акции, страница бренда, поиск, вход и регистрация, список заказов, избранное, «Сервисный центр», «Запчасти», «Сотрудничество», 404.
